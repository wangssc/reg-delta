# 制度差分 · reg-delta

> 新规下来，最怕改了正文忘了台账。新旧两版逐条拆成四个要素，只说哪几条真变了、变在主体还是时限还是阈值、你哪份文件的哪一句要跟着改。

对同一套规则、制度、政策或合规文件的新旧版本做逐条比对，产出三样东西：**变了什么**（可追溯到条款位置 + 生效日期）、**影响哪份内部资产**（落到具体文件某一句）、**该怎么改**（可执行的修改动作）。纯措辞调整自动过滤，不刷屏。

## 它能回答什么

| 你说 | 它做 |
| --- | --- |
| 「这两版管理办法到底哪里不一样」 | 逐条义务要素比对，滤掉纯措辞与位置调整 |
| 「新规出来了，我这几份制度要改哪」 | 把每条变化映射到内部制度/台账的具体句子 |
| 「只改了措辞的别报」 | 四类要素（主体/动作/对象/时限阈值）任一未变即不报 |

## 三条红线（不可让渡）

1. **规则内容只来自用户提供的文件。** 不联网、不搜索、不凭训练记忆补任何条文。拿不到来源时，唯一正确输出是「本期未取得可核实来源，不出报告」。
2. **每条变化必须绑定条款位置与生效日期。** 没有位置的变化是印象不是发现；没有生效日期就标「待核」，且该条不计入确定结论。
3. **示例不出现真实机构名/法规名/条款号。** 测试与模板一律用明显不存在的虚构命名。

红线 3 是刻意设计的：这个 skill 是给用户自供文本做差分的，一旦它开始凭记忆写真实条文，就已经越界成法律意见了。

## 它不做什么

- 不提供法律意见，不判断处罚后果，不预测执法尺度。
- 不写立法沿革、行业影响、免责话术。
- 法规条文查询是搜索的事，合规判断是律师的事。

## 装成 Skill 用

复制整个目录到 `~/.workbuddy/skills/reg-delta/`，然后同时提供基线版与新版文本，说「比对这两版」。入口是 [`SKILL.md`](SKILL.md)。

## 目录

```
reg-delta/
├── SKILL.md                        流程、红线、三段式输出、状态管理
├── DESIGN-NOTES.md                 设计判断与推翻
├── references/
│   ├── classification.md           四类义务要素与变化分类
│   ├── impact-mapping.md           内部资产映射方法
│   └── source-grading.md           来源分级
├── templates/                      基线与报告模板
└── samples/                        虚构示例（含一次完整输出）
```

## 已知边界

只做文本到文本的映射，不联网、不凭记忆引用条文、不给法律意见。示例里的机构名和法规名全是虚构的，是为了避免被当成真实依据。
